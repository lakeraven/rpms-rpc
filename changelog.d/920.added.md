`RpmsRpc::Crs` runs the CRS National GPRA report and the National GPRA patient lists through the Visual CRS RPCs (`BGPG 25 ...`, context option `BGPGRPC`) (#920)

- Reads: `site_parameters` (BGP SITE PARAMETERS: location, home location, community taxonomy, EISS), `community_taxonomy(ien)` (the warnings `COMCHK^BGPXGUA` raises about communities missing from the standard table; a clean taxonomy has none), `taxonomies` (the CRS package taxonomies with their state, kind and file), `indicators` (the National GPRA measures) and `report_output(report_ien)` (the lines of a finished report, page breaks kept).
- Queues: `queue_national_gpra(community_taxonomy:, name:, ...)` and `queue_patient_lists(community_taxonomy:, name:, lists:, period:, baseline_year:, population:, ...)` build the `|`-piece strings `NTL^BGPXGR` and `NPL^BGPXGR` read and return `{ report_ien:, raw: }`. A refusal raises `Crs::QueueRefusedError`, with CRS's reason for the National GPRA report; the patient-list RPC answers only the number, so its refusal has none.
- `report_status` lists the signed-on user's CRS reports. It is classified a write: `CHK^BGPXGU` deletes a report with no end time whose start is more than seven days old while it lists. `wait_for_report(report_ien, timeout:)` polls it until the report completes, and raises `Crs::ReportFailedError` (errored, or no longer listed) or `Crs::TimeoutError` (naming the report and its last status).
- Refused before anything is sent: a value carrying `|`, `~` or `^`, an ien that is not a positive integer, a blank report name, an unknown output type or population, a period without a quarter 1-4 or an end date, and a patient-list request without a measure and list.
- A trapped M error (the `T00250MError` table, or an `ERROR|` row) raises `Crs::ServerError` carrying the M error text; a reply without its typed header raises `Crs::ReplyError`. Neither is an empty list. A broker refusal of the context propagates as the client's own typed error.
- Every method binds `BGPGRPC`, the one option the RPCs are registered under. On bcer-9.0-20261119-f67498c-ydb only the operator account can run them (no persona holds `BGPGRPC`), and the build refuses both queue RPCs (`0^COULD NOT CREATE REPORT ENTRY`; openrpms#1305).
- The report output is read over CIA: `ONTL^BGPXGR` writes its trap label after the `$C(31)` end node, which `BmxClient` reads as a query error.

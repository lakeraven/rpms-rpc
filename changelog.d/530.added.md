`SchedulingSetup.creates_visit_at_checkin` reads whether check-in creates the PCC visit (#530)

- `creates_visit_at_checkin(hospital_location_id)` reads #9009017.2 (the hospital location's IHS scheduling companion entry) field .09 CREATE VISIT AT CHECK-IN with `DDR GETS ENTRY DATA` in `CIAV VUECENTRIC`. `CHECKIN^BSDX25` (`BSDX CHECKIN APPOINTMENT`) creates the PCC visit through `GETVISIT^BSDAPI4` only when that field's external value is `YES` (BSDX25.m:138: `I $$GET1^DIQ(9009017.2,+BSDXC("HOS LOC"),.09)'="YES" Q`). .09 is a set of codes whose internal `1` is external `YES` (observed live); the method checks internal `1`.
- The read is fail-closed. An IEN that is not a positive integer returns nil and sends no RPC. True only when .09 is YES. False when the entry exists and .09 is NO or empty. A clinic with no #9009017.2 entry raises `Client::RpcError`, as do a nil or error reply. DDR GETS ENTRY DATA for a missing entry answers the bare reply `["[ERROR]"]` (GETS^DIQ raises DIALOG 601, DDR2 writes only `[ERROR]`), and over the wire a missing entry cannot be told from another failure. M itself treats a missing entry as no visit, so a host that gets the raise must not assume check-in will create the visit.

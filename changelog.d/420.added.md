Stock RPC wrappers for sensitive access, the security audit, Mailman, and scheduling (#420)

- `Agg.check_sensitive_patient`, `Agg.send_sensitive_notify`, and `Agg.error_screen` wrap the AGGRPC RPCs. `Bgu.send_mailman_message` (`CIAV VUECENTRIC`), `Busa.log_security_audit` (`BUSARPC`), `DgSensitive.check_access` and `DgSensitive.record_bulletin` (`OR CPRS GUI CHART`), and `Orwu.fileman_datetime` (`CIAV VUECENTRIC`) are new modules. `Scheduling.resources_by_user` reads `BSDX RESOURCES BY USER`. `Scheduling.checkin_visit` reads `BEHOENCX GETVISIT` under `CIAV VUECENTRIC`.
- `FND^AGGEDCHK` writes a header and no data row on this pin (`FER`'s row write is commented out). A header-only reply is an empty list. `PTSEC^DGSEC4` returns 5 for restricted access; the wrapper keeps 5. The #8994 return text still stops at 4.
- Sensitive-record access and the security-audit write fail closed. A blank DFN does not call `DG SENSITIVE RECORD ACCESS`. A BUSA piece that contains `|` is refused before the call. A reply that is not the routine's success value is not success. `DgSensitive.check_access` writes the DG SECURITY LOG (`DGSEC4.m:65`) and `Agg.check_sensitive_patient` audits the lookup through `SENS^DGSEC4` (`AGGPTSEN.m:30`), so both are `:non_idempotent_write`. `EN^BGUMAIL` sets 1/OK unconditionally after `D ^XMD` (`BGUMAIL.m:5-6`); `success: true` means the routine ran, not that the group exists or that mail was delivered. A DFN that is not a positive integer never reaches `AGG CHECK SENSITIVE PATIENT`, `AGG SEND SENSITIVE NOTIFY`, `DG SENSITIVE RECORD ACCESS`, or `DG SENSITIVE RECORD BULLETIN`. `BUSA LOG SECURITY AUDIT ENTRY`, `BGU MAILMAN MESSAGE`, `AGG CHECK SENSITIVE PATIENT`, `AGG SEND SENSITIVE NOTIFY`, `DG SENSITIVE RECORD ACCESS`, `DG SENSITIVE RECORD BULLETIN`, are `:non_idempotent_write`. `DgSensitive.parse_access_reply` reads the access code in base 10, so a leading zero is decimal.

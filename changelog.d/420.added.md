Stock RPC wrappers for sensitive access, the security audit, Mailman, and scheduling (#420)

- `Agg.check_sensitive_patient`, `Agg.send_sensitive_notify`, `Agg.error_screen`, and `Agg.update_legal_names` wrap the AGGRPC RPCs. `Bgu.send_mailman_message` (`CIAV VUECENTRIC`), `Busa.log_security_audit` (`BUSARPC`), `DgSensitive.check_access` and `DgSensitive.record_bulletin` (`OR CPRS GUI CHART`), and `Orwu.fileman_datetime` (`CIAV VUECENTRIC`) are new modules. `Scheduling.resources_by_user` reads `BSDX RESOURCES BY USER`. `Scheduling.checkin_visit` reads `BEHOENCX GETVISIT` under `CIAV VUECENTRIC`.
- `BSDX CHECKIN APPOINTMENT` now sends the pinned tag's eleven client inputs. The twelfth formal, `BSDXY`, is the return value the broker passes by reference. FOIA's `CHECKIN^BSDX25` stops at `BSDXOG`.
- `FND^AGGEDCHK` writes a header and no data row on this pin (`FER`'s row write is commented out). A header-only reply is an empty list. `PTSEC^DGSEC4` returns 5 for restricted access; the wrapper keeps 5. The #8994 return text still stops at 4.
- Every `Agg.update_legal_names` proc allowlists PARMS against `^AGG(9009068.3,27,10,"AC")` (`RIEN` and `DFN` are not parameters). A non-Hash or a repeated name is `:invalid_param` and sends no RPC. A blank-RIEN add files one absolute `AGGLNDTC` (`MM/DD/YYYY`): the caller's, or server today from `ORWU DT` `"T"` when the caller left it blank. There is no `DT` fallback. `ORWU DT` `"TS"` must return that day's FileMan date (`DATE^AGGUL1`, `AGGUL1.m:28-34`). It then locks `^AUPNNAMC("B",day)` (`DDR LOCK/UNLOCK NODE`, `LOCKC^DDR1`, `DDR1.m:18-30`) and reads that one day on file 9000033's B index (`^DD(9000033,0,"IX","B",9000033,.01)`). `^DIC` with `DIC(0)="L"` (`AGGPTNAM.m:81`) would otherwise select another patient's row on that date. The stock GUI and other clients do not take the lock, so the post-check stays the backstop: a concurrent non-wrapper add on the same day is still only detectable when it selects an IEN at or below the prior max. The pre-check is read-then-write, not atomic. An IEN that already existed, or whose `.02` is not this DFN, is `:legal_name_takeover` with `written: true`; that post-check cannot undo the filing. `DgSensitive.parse_access_reply` reads the access code in base 10, so a leading zero is decimal.
- Sensitive-record access, the security-audit write, and legal-name updates fail closed. A blank DFN does not call `DG SENSITIVE RECORD ACCESS`. A BUSA piece that contains `|` is refused before the call. A reply that is not the routine's success value is not success. `DgSensitive.check_access` writes the DG SECURITY LOG (`DGSEC4.m:65`) and `Agg.check_sensitive_patient` audits the lookup through `SENS^DGSEC4` (`AGGPTSEN.m:30`), so both are `:non_idempotent_write`. `EN^BGUMAIL` sets 1/OK unconditionally after `D ^XMD` (`BGUMAIL.m:5-6`); `success: true` means the routine ran, not that the group exists or that mail was delivered. A non-blank legal-name RIEN is checked against file 9000033 field `.02` before `LEGL` (`AGGPTNAM.m:72`, `:83`); that check is a read-then-write, not atomic. A DFN that is not a positive integer never reaches `AGG CHECK SENSITIVE PATIENT`, `AGG SEND SENSITIVE NOTIFY`, `AGG UPDATE LEGAL NAMES`, `DG SENSITIVE RECORD ACCESS`, or `DG SENSITIVE RECORD BULLETIN`. `BUSA LOG SECURITY AUDIT ENTRY`, `BGU MAILMAN MESSAGE`, `AGG CHECK SENSITIVE PATIENT`, `AGG SEND SENSITIVE NOTIFY`, `DG SENSITIVE RECORD ACCESS`, `DG SENSITIVE RECORD BULLETIN`, and `AGG UPDATE LEGAL NAMES` are `:non_idempotent_write`.

Closes #420.

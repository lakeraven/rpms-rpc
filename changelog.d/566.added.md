Tribal enrollment reads are captured live on the pinned build (#566)

- `WireCapture::CatalogEntry` takes an optional fixture name. `fixture_name` is that name, or the RPC slug when it is omitted, so existing captures keep their file names. `WireCapture.fixture_path` writes `test/fixtures/wire_captures/<fixture_name>.yml`.
- `Fixture.load_all` returns every fixture file. `WireCapture.compare` and `rake wire:compare` key and print that basename, so a second capture of one RPC is its own row.
- `rake wire:capture` keys the driver reply and the fixture lookup by fixture name, and `ONLY` / `CITE_ONLY` match either the RPC name or the fixture name. The driver still calls reads only.
- A whole-value `UNKNOWN` (any case) is not wire evidence.
- Eight tribal DDR reads are catalogued with the parameters `Tribal` sends and were captured as PROV123. Tribe and community lists use `part: "OTHER"` and `part: "STONEHAM"`. `docs/pilot_rpc_readiness.md` grades each Tribal method from those captures. Enrollment stays partial: `.07` is blank on every seed patient, and DFN 2's community is the UNKNOWN filler. The Eligibility-window write is graded from the live spec, which files BENEFICIARY #9999999.25 IEN 1 OTHER.

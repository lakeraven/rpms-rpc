`BehavioralHealth.save_visit` re-binds the DDR context on every exit after the AMHG call (#537)

- A session with no declared context is re-bound to `CIAV VUECENTRIC` after `AMHG SAVE VISIT` even when that call raises `Client::ConnectionError` (including a timeout) or `Client::RpcMError`, so it is no longer left on `AMHGRPC`. The exception in flight is captured at the call, not read from `$!`, so a caller already inside `rescue` still sees a failed re-bind as `SaveError`; a failed re-bind never replaces a `SaveError` the call already raised.
- **Error contract change.** A plain `Client::RpcError` (not `RpcNotAvailableError`, `RpcRefusedError` or `RpcMError`) raised by the AMHG call in `save_visit`, `save_progress_note` and `save_pov` is now `SaveError` with an unknown outcome, the `RpcError` kept as the cause and no broker text, instead of propagating. A host that rescued `Client::RpcError` around those calls must rescue `SaveError` too. On that path, and on a timeout or `RpcMError`, `save_pov` and `save_progress_note` now re-bind a session with no declared context to `CIAV VUECENTRIC` before raising; a failed re-bind does not replace the error.

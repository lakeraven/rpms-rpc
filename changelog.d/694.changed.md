`HealthSummary.reminder_detail` sends the patient and the reminder as two parameters, and `clinical_reminders` reads the row the build writes (#694)

- `reminder_detail(dfn, reminder_ien)` sent `ORQQPX REMINDER DETAIL` one `"DFN^IEN"` parameter. `REMDET^ORQQPX` takes them as two formals, so the reminder was undefined and every call died in M (LVUNDEF). It now sends two, and returns the reminder's text.
- `clinical_reminders` read `ORQQPX REMINDERS LIST` as `ien^name^status^due_date^last_done^priority`. The build's `REMIND^ORQQPX` (OR*3.0*226) answers `IEN^NAME^DUE DATE^LAST DONE^PRIORITY^DUE FLAG^DIALOG^^^^WIPE`, so "DUE NOW" landed in `:status`, the due date was lost and the due flag read as the priority. Each reminder is now `{ ien:, name:, due_date:, last_done:, priority:, due_flag:, dialog:, dialog_wipe: }`, the same pieces as `ORQQPXRM REMINDERS APPLICABLE`. `:status` is gone: callers read `due_flag` (1 due, 2 not due, 3 error, 4 cannot be determined), and `due_date` stays raw so "DUE NOW" survives. `priority` is an Integer.

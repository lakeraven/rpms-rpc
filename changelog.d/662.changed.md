`HealthSummary.for_patient` prints an IHS health summary type the site lists (#662)

- **Breaking.** `for_patient(dfn, summary_type: "ADULT REGULAR")` resolves the type, by name in any case or by IEN, against the IHS health summary types the site lists, and runs the IHS report (`ORWRP REPORT TEXT` with RPTID `IHS`, HS^ORWRPBHS) for that IEN. It used to send report 1 with type IEN 1 from an invented table (STANDARD, BRIEF, COMPREHENSIVE, PATIENT): report 1 reads HSTYPE as a VA type (#142), and VA type 1 faults (`ERR+9^ORWRP`). The default type is now `ADULT REGULAR`, and the old names are not types on the build.
- `HealthSummary.summary_types` is new: the `x` rows of the `[HEALTH SUMMARY TYPES]` block of `ORWRP REPORT LISTS`, the list the reports tab offers (GETHS^ORWRPBHS), as `[{ ien: "7", name: "ADULT REGULAR" }, ...]`. The `h` rows beside them are VA types and are left out.
- **Breaking.** A type the site does not list sends no report and answers an error summary naming it, instead of falling back to another type. A report that faults on the server is an error summary.
- **Breaking.** Sections are the report's own banners (`ACTIVE PROBLEMS (ALL)`, `CURRENT MEDICATIONS (max 6 visits or 6 months)`, ...). Page banners are dropped and a section that runs onto the next page is one section. `component_data` picks the section whose banner is, or ends with, the component's name.
- Proven live on a throwaway container of bcer-9.0-20261110-55d9e3e-ydb (`test/live/health_summary_live_test.rb`): every listed type prints without a fault. The replies are pinned as captures.

`RpmsRpc::Coverage.delete_private_insurance` removes one private policy row through DDR FILER (#382)

- `delete_private_insurance(dfn, record_ien:)` deletes one #9000006.11 policy row for that patient. It reads `.01` with child-first IENS `"<record_ien>,<dfn>,"` and flags `I` on the caller's client first. A reply that does not answer is `:verification_failed` and nothing is listed or written. A filed `.01` proceeds to the filer. A FileMan error or a blank `.01` runs one `DDR LISTER` of #9000006.11 with IENS `",<dfn>,"`, fields `@;.01`, flags `IP`, MAX `*`, and XREF `#` (LIST^DIC walks the record numbers, not the B index, so a row missing from the B index is still listed and never read as absent). When that list is a positive answer (non-nil, `error` false, a data section, no `MORE`) whose entries do not include the record IEN, the result is `{ success: false, error: :already_absent, message: "private insurance <record> is not on file for patient <dfn>", record_ien: }`. Any other list is `:verification_failed`. Neither path sends `DDR FILER`. Absence alone is not verified.
- The write is one `DDR FILER` EDIT, field `.01` set to `@`, under `CIAV VUECENTRIC`. `AGG UPDATE PRIVATE INSUR` with PROC D is not sent: `UPD^AGGUPPVT` sets `AGGUPD(FILE,IENS,.01)="@"` before `IENS` is set (`AGGUPPVT.m:36-39`). After the filer reports success, the same packed `DDR LISTER` (fields `@;.01`, flags `IP`, MAX `*`, XREF `#`) must be a positive answer that does not list the record IEN. Still listed, a nil reply, a FileMan error, no data section, or a `MORE` continuation is `:verification_failed`. A FileMan error on the list is never absence. A filer refusal is `:delete_failed`. Success is `{ success: true, record_ien: }`.

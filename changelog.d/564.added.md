`WireCapture` records a TIU progress-note write on the owned loopback rung (#564)

- Catalog entries for TIU CREATE RECORD, TIU LOCK RECORD, TIU SET DOCUMENT TEXT, TIU GET RECORD TEXT, TIU UNLOCK RECORD, and TIU SIGN RECORD are `mode: :write`. A `WRITES=1` run calls none of the read catalog.
- `WRITES=1` runs create, lock, set text, read-back, unlock, and sign through `ProgressNote` and `ESignature`. Sign runs only when create succeeded, the lock was held, `update_text` succeeded, the `TIU GET RECORD TEXT` raw passes `WireCapture.write_evidence?` with `note_body: NOTE_TEXT` and that note IEN, and unlock returned true. A failed set text is not read back. A lock call that raises is followed by one unlock (`UNLOCK^TIUSRVP` always answers 0) and then nothing else. A held lock is unlocked even if set text or the read-back raises. A capture whose reply or inputs contain the signature code is dropped, not rewritten; the stored sign input is `[signature code withheld]`.
- The run is refused before a socket unless the broker host resolves to loopback addresses only, `CONTAINER` is unset, and the access code is a README synthetic persona (`SYS123` or `PROV123`). A write run connects to that resolved loopback address, not the host name. A blank `ONLY` (empty or whitespace) is unset. A non-blank `ONLY` is refused, because the TIU flow is captured together and a write run calls no read RPC. `RPMS_ESIG`, when set, must be 6-20 characters with no leading or trailing whitespace (NEW PERSON field 20.4 stores the exact code); a blank, surrounding whitespace, or any other length is refused. The refusal never includes the code or the access value. Set-text evidence has to name the captured note IEN. The read-back has to contain the whole note, each body line within `ProgressNote::WRAP_WIDTH`. A reply the public API does not accept does not replace an existing fixture. A write run writes only the TIU write fixtures, never a read or routine-cite one.

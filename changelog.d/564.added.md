`WireCapture` records a TIU progress-note write on the owned loopback rung (#564)

- Catalog entries for TIU CREATE RECORD, TIU LOCK RECORD, TIU SET DOCUMENT TEXT, TIU GET RECORD TEXT, TIU UNLOCK RECORD, and TIU SIGN RECORD are `mode: :write`. A `WRITES=1` run calls none of the read catalog.
- `WRITES=1` runs create, lock, set text, read-back, unlock, and — when `RPMS_ESIG` is a non-blank string — sign, through `ProgressNote` and `ESignature`. A held lock is unlocked even if set text or the read-back raises, and sign does not run after a failure. A capture whose reply or inputs contain the signature code is dropped, not rewritten; the stored sign input is `[signature code withheld]`.
- The run is refused before a connection unless the broker host resolves to loopback addresses only, `CONTAINER` is unset, and the access code is a README synthetic persona (`SYS123` or `PROV123`). Set-text evidence has to name the captured note IEN. The read-back has to contain the whole note, each body line within `ProgressNote::WRAP_WIDTH`. A reply the public API does not accept does not replace an existing fixture.

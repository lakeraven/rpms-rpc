`Encounter.save` files a whole encounter through BEHOENPC SAVE: the visit, its diagnoses, procedures, health factors and primary provider, in one call (#921)

- `Encounter.save(dfn, location_ien:, datetime:, service_category:, provider_duz:, diagnoses: [], procedures: [], health_factors: [])` sends the PCC list `SAVE^BEHOENPC` reads (HDR, VST, PRV, POV+, CPT+, HF+). It reads the visit and every entry back through the gem's existing readers, before and after, and counts only rows the save added to that visit. Success means everything requested was read back. Anything less is `:partial`, naming what did and did not file.
- Each diagnosis is linked to the problem list by the build: `POV^BEHOENPC` calls `$$PROBLST^BEHOENP2` unconditionally, which reuses the patient's problem for the SNOMED concept or files a new one. The result names each diagnosis's `problem_ien`. The gem sends no problem-list RPC itself.
- Refused before anything is sent: a diagnosis with no SNOMED concept (rpms-rpc#704), any value carrying `^`, `;` or `|`, and a blank required argument. A server `-N^text` reply is `:refused`, and the visit is still read back: `SAVE^BEHOENPC` keeps the lines before the one that failed, so the result names what filed and what did not.
- The visit is read with `BEHOENCX FETCH` CREATE=0, which can never add a visit. `may_have_filed` is true whenever `BEHOENPC SAVE` was sent, including when the read after it fails (`:read_back_failed`) or no reply comes back (`:save_failed`).
- Published at `POST /patients/{dfn}/encounters/pcc`, next to `Encounter.create`'s `POST /patients/{dfn}/encounters`.

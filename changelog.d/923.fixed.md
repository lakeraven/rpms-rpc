`Problem.add` and `Problem.update` refuse a status BGOPROB SET does not know, instead of letting it file as EPISODIC (#923)

- `status:` takes the names PROB^BGOPROB3 files (Chronic, Inactive, Sub-acute, Episodic, Social/Environmental, Routine/Admin, Admin) or the `.12` letter each files as (A, I, S, E, O, R), in any case. The exact name is what is sent, so `status: "A"` now files as A (CHRONIC). It filed as E before.
- Any other value is refused with the failure hash, naming the status, before anything is sent. That covers D and Deleted (`Problem.delete` deletes), a value containing `^`, and a value that is not a String. On `update` the refusal comes before the patient check, so nothing reaches the wire.
- An omitted, nil or empty status is unchanged: piece 8 is empty and the build applies its own default (BGOPROB3.m:113-114).

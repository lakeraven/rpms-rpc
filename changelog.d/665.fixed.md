`Vital.validate` sends BEHOVM VALIDATE the frame its routine reads (#665)

- `validate(dfn, measurements, metric: -1)` now sends each measurement as `VALIDATE(DATA,VCTL,METRIC,X)` reads it: the vital type's abbreviation, the units flag (-1 the type's default units, 0 US, 1 metric) and the value. It used to send `"<abbrev>|<value>"` and the DFN, which left X undefined, so every measurement died in M (`VALIDATE+3^BEHOVM`, LVUNDEF). The DFN is still accepted and is not sent: VALIDATE takes no patient.
- A value the build refuses answers `-1^<reason>` (a filed value never holds a caret); the error carries that reason (`Input must be between 70 and 120 F.`). A value it accepts is valid even when the build converts it to the type's default units (`36C` answers `96.8`). A vital type the build does not have faults in the routine; that measurement is an error, not a raise.
- Proven live on a throwaway container of bcer-9.0-20261110-55d9e3e-ydb as PROFILE,MD and PROFILE,RN (`test/live/vital_validate_live_test.rb`), with the replies pinned as captures.

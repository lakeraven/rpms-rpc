`RpmsRpc::Vital.add_stock` saves vitals through stock VistA `GMV ADD VM`, and reports success only when `GMV EXTRACT REC` reads the new row back (#458)

- Each measurement is one `GMV ADD VM` call with the record `DATETIME^DFN^TYPE_IEN;READING;^LOCATION^DUZ*QUAL:QUAL` (`EN1^GMVDCSAV`, `GMVDCSAV.m:14-30`). The type IEN comes from `GMV GET VITAL TYPE IEN`.
- Abbreviations are GMV's (BP, T, P, R, HT, WT, PN, PO2, CG, CVP), in US units. A value `GMVDCCHK` would refuse, an unknown type or other units raise `ArgumentError` before any RPC is sent.
- The type's rows in the minute after `taken_at` are listed before and after the save; only a new row carrying the value is success. An `ERROR:` reply, an empty read-back or no new row is failure. It is not atomic: `saved` names what was filed before a failure.

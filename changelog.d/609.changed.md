Registration's duplicate lookup runs over BMX; over CIA it needs `Registration.with_lookup_client` (#609)

- Over CIA an M error inside `AGG LOOKUP PATIENTS` answers the same bytes as a genuine no-match (ERR^AGGPTLKP writes the `$C(31)` DONE writes; its only signal, `BMXSEC`, reaches a BMX client alone). A faulted lookup could read as "no candidates" and let a retry file a second chart.
- `RpmsRpc::Registration.with_lookup_client(bmx) { ... }` scopes a `BmxClient` signed on as the same user. Inside it, the duplicate lookup runs on that client, and every other call stays on `RpmsRpc.client`. Over CIA with no lookup client scoped, registration answers `:identity_unverifiable` and sends nothing. A client that is not a signed-on `BmxClient` raises `ArgumentError`. One that does not show the same DUZ, bound division and division list is `:identity_unverifiable`. When `RpmsRpc.client` speaks BMX, the lookup runs on it as before. The `register` signatures are unchanged.
- Proven on a throwaway container of bcer-9.0-20261109-d3adcff-ydb: a no-match over BMX reads as no match, a match is a duplicate, and a faulted lookup fails closed (`test/live/registration_lookup_bmx_live_test.rb`). Live registration specs over CIA now need `BMX_PORT`.

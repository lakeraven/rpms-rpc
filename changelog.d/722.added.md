`Referral.record_follow_up` files a date of service and a case note on an open referral through BMC UPDATE REFERRAL in 30 parameters, and `Referral.follow_up_state` reads them back; `Referral.record_status` files a checked STATUS OF REFERRAL through BMC REFERRAL STATUS UPDATE. Both decide success by reading the record back (#722)
Live-verified on the pinned build as PROV123 and PMD123 (`test/live/referral_follow_up_live_test.rb`, `test/live/referral_status_live_test.rb`). UPDREFRL^BMCRPC2 has 36 formals with RSLT and YottaDB takes 32 actual arguments, so record_follow_up sends REFIEN through CN (31 actuals). The routine rewrites the record: the INCLUDE flags (401-412), the one SNOMED CT term and the date of service on file are read first and resent, the time is sent as canonical FileMan digits, and a closed referral, one linked to an EHR referral (1303), and one with several SNOMED CT terms are refused before anything is written. UPDTSTRF^BMCRPC3 files any string as the status and, after one failed update, re-files that failed write on every later call in the same broker session, so record_status checks the code set first and answers `:session_poisoned` on a refusal reply.

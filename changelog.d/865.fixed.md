The server-clock application live spec passes when run again on the same container the same day (#865)

- `test/live/server_clock_writes_live_test.rb` filed its application, dated the server's today, on one fixed seed patient. A patient holds one application per date obtained, so every later run that day on that container failed with "an application obtained on <today> is already on file".
- It now registers its own synthetic patient for each run and files the application there. It still proves the same thing: the server's tomorrow is refused, its today is accepted, and the stamp and the default status date are the server's day. It also checks the new patient has no application and no .16 stamp before the write, so the stamp it reads back is the one this write made.

Sex, SOGI and MBI through DDR, and holiday maintenance (#418)

- `Registration.set_gender_identity`, `set_sexual_orientation`, `set_legal_sex`, `add_mbi`, and `set_sex` file through DDR FILER under `CIAV VUECENTRIC`. `set_sex` is the `AG2A` `.23` delete plus `SEXELIG^AGUTL`, and the order deliberately differs from `AG2A`. `AG2A` files `#2` `.02` interactively first. This method clears `#9000001` `.23` first when the sex changes and that field is non-blank, then files `#2` `.02` (mode EDIT), then copies the sex onto the MCR, MCD, and RRE eligibility rows. Filing `.02` first left a failed `.23` delete unrepairable: a retry pre-reads the new sex and skips the delete, leaving SSN VERIFICATION STATUS set for a sex that changed. With `.23` first, a half-done run leaves `.23` cleared and `.02` unchanged, and a retry sees the stored sex differ and `.23` blank, skips the delete, files `.02`, runs the cascade, and finishes. The end state on success is the same as `AG2A`'s. The writes are not atomic; a refusal after an earlier EDIT succeeded is `:partial`. A retry after `:partial` finishes the job. A `:partial` on the cascade is retried by repeating the call, and the cascade always runs when rows exist and the earlier EDITs on that call succeeded. `Registration.mbis` reads `#9000001` `.01` before listing `#9000001.44` and raises `Client::RpcError` when that entry is missing or either read fails. `set_insurance_billing_order` and `insurance_in_use` return `{ success: false, error: :not_supported }` and send no RPC.
- `SchedulingSetup.add_holiday` and `remove_holiday` maintain HOLIDAY (`#40.5`) through DDR FILER. A missing holiday is `:not_found` and does not file. After strip, a holiday name that contains `^`, a control character, or is exactly `@` is `{ success: false, error: :invalid }` and sends no RPC. Ordinary text still files.
- DDR FILER writes the internal fields and does not run the M tag's code translation, defaults, or cross-file updates. FileMan xrefs on those fields still fire. `set_sex` issues the `SEXELIG^AGUTL` eligibility edits as their own DDR FILER calls; they are not a cross-reference on `#2` `.02`. `Registration.update(dfn, sex:)` still goes through AGG UPDATE PATIENT and files `#2` `.02` without `SEXELIG^AGUTL`. See `docs/REGISTRATION_SCHEDULING_WRITES.md`.
- `Registration.set_sex` files each write as its own DDR FILER EDIT. The order deliberately differs from `AG2A`, which files `#2` `.02` interactively first: `#9000001` `.23` is set to `"@"` first, only when the sex changes and `.23` is non-blank, then `#2` `.02` always, then the eligibility cascade when rows exist. Filing `.02` first left a failed `.23` delete unrepairable, because a retry pre-reads the new sex and skips the delete, leaving SSN VERIFICATION STATUS set for a sex that changed. With `.23` first, a half-done run leaves `.23` cleared and `.02` unchanged; a retry sees the stored sex differ and `.23` blank, skips the delete, files `.02`, runs the cascade, and finishes. The end state on success is the same as `AG2A`'s. A refusal of the first call, or a reply with no `[Data]`, is `:filer_failed` and later calls are not sent. No reply on the first call returns nil. A refusal, a reply with no `[Data]`, or no reply on a later call is `:partial`. When `#2` `.02` fails after the `.23` delete, the message names `#2` `.02` and says it was not filed (refusal or no `[Data]`) or, on no reply, may not have been filed, keeping "the outcome of the last write is unknown", and says `#9000001` `.23` was already cleared. A cascade failure names eligibility. A retry after `:partial` finishes the job. A `:partial` on the cascade is retried by repeating the call, and the cascade always runs when rows exist and the earlier EDITs on that call succeeded.
- `DdrFileman.gets_entry` returns `malformed: true` exactly when the reply has neither `[Data]` nor `[ERROR]` and no fields parsed, and `malformed: false` otherwise. `error` and `fields` are unchanged. When the `#2` `.02` or `#9000001` `.23` read is malformed, `Registration.set_sex` returns `:lookup_failed` and the message names the file and field. A genuine `[ERROR]` reply stays `:not_found`. The gender-identity and sexual-orientation code read checks `malformed` before `error`: `malformed: true` is `:lookup_failed` and the message names the file and field 1; a genuine `[ERROR]` reply stays `:invalid`.
- `DdrFileman.filer` sets `success` true only when the reply contains `[Data]` and the error block is empty. `FILEC^DDR3` emits `[Data]` first on a completed call. A reply with no `[Data]` is `success: false`, and `errors` names the missing marker and includes the reply's first line. nil stays nil. Placeholder `+n,^IEN` parsing is unchanged. Writers built on `filer` use that flag: a reply with no `[Data]` is `:filer_failed`, or `:partial` on a later `set_sex` EDIT.
- After strip, `other` on `set_gender_identity` and `set_sexual_orientation` is refused before any RPC when it contains `^`, a control character, or is exactly `@`. The refusal is `{ success: false, error: :invalid }`. Ordinary text still files.

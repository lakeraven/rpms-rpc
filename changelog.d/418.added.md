Sex, SOGI and MBI through DDR, and holiday maintenance (#418)

- `Registration.set_gender_identity`, `set_sexual_orientation`, `set_legal_sex`, `add_mbi`, and `set_sex` file through DDR FILER under `CIAV VUECENTRIC`. `set_sex` is the `AG2A` `.23` delete plus `SEXELIG^AGUTL`: it files `#2` `.02` first (mode EDIT), then clears `#9000001` `.23` when `#2` `.02` changes and that field is non-blank, then copies the sex onto the MCR, MCD, and RRE eligibility rows. The cascade is not atomic with the `.02` write; a refusal after an earlier EDIT succeeded is `:partial`. A retry after `:partial` files `#2` `.02` again when the pre-reads succeed. It does not re-evaluate the `#9000001` `.23` delete once `.02` has landed (the stored sex equals the new code, so the delete is not sent), and a failed `.23` delete has to be cleared in RPMS. The cascade runs again when rows exist and the earlier EDITs on that call succeeded. `Registration.mbis` reads `#9000001` `.01` before listing `#9000001.44` and raises `Client::RpcError` when that entry is missing or either read fails. `set_insurance_billing_order` and `insurance_in_use` return `{ success: false, error: :not_supported }` and send no RPC.
- `SchedulingSetup.add_holiday` and `remove_holiday` maintain HOLIDAY (`#40.5`) through DDR FILER. A missing holiday is `:not_found` and does not file. After strip, a holiday name that contains `^`, a control character, or is exactly `@` is `{ success: false, error: :invalid }` and sends no RPC. Ordinary text still files.
- DDR FILER writes the internal fields and does not run the M tag's code translation, defaults, or cross-file updates. FileMan xrefs on those fields still fire. `set_sex` issues the `SEXELIG^AGUTL` eligibility edits as their own DDR FILER calls; they are not a cross-reference on `#2` `.02`. `Registration.update(dfn, sex:)` still goes through AGG UPDATE PATIENT and files `#2` `.02` without `SEXELIG^AGUTL`. See `docs/REGISTRATION_SCHEDULING_WRITES.md`.
- `Registration.set_sex` files each write as its own DDR FILER EDIT, in this order: `#2` `.02` first, then the `#9000001` `.23` delete only when the sex changes and `.23` is non-blank, then the eligibility cascade when rows exist. A refusal of the first call is `:filer_failed` and later calls are not sent. No reply on the first call returns nil. A refusal or no reply on the `.23` delete or the cascade, after `.02` succeeded, is `:partial`. The `.23` message names `#9000001` `.23` SSN VERIFICATION STATUS: a refusal says it was not cleared, and a no-reply says the outcome of the last write is unknown and that it may not have been cleared. A cascade failure names eligibility. The no-reply wording "the outcome of the last write is unknown" stays. A retry after `:partial` files `#2` `.02` again when the pre-reads succeed. It does not re-evaluate the `.23` delete once `.02` has landed (the stored sex equals the new code, so the delete is not sent). The cascade runs again when rows exist and the earlier EDITs on that call succeeded. A failed `.23` delete has to be cleared in RPMS.
- `DdrFileman.gets_entry` returns `malformed: true` exactly when the reply has neither `[Data]` nor `[ERROR]` and no fields parsed, and `malformed: false` otherwise. `error` and `fields` are unchanged. When the `#2` `.02` or `#9000001` `.23` read is malformed, `Registration.set_sex` returns `:lookup_failed` and the message names the file and field. A genuine `[ERROR]` reply stays `:not_found`. The gender-identity and sexual-orientation code read checks `malformed` before `error`: `malformed: true` is `:lookup_failed` and the message names the file and field 1; a genuine `[ERROR]` reply stays `:invalid`.
- `DdrFileman.filer` sets `success` true only when the reply contains `[Data]` and the error block is empty. `FILEC^DDR3` emits `[Data]` first on a completed call. A reply with no `[Data]` is `success: false`, and `errors` names the missing marker and includes the reply's first line. nil stays nil. Placeholder `+n,^IEN` parsing is unchanged. Writers built on `filer` use that flag: a reply with no `[Data]` is `:filer_failed`, or `:partial` on a later `set_sex` EDIT.
- After strip, `other` on `set_gender_identity` and `set_sexual_orientation` is refused before any RPC when it contains `^`, a control character, or is exactly `@`. The refusal is `{ success: false, error: :invalid }`. Ordinary text still files.

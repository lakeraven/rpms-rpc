Note-keyed PCE reads refuse another patient's note (#531)

- On a positive note IEN, `ORWPCE GET VISIT`, `ORWPCE HASVISIT` and `ORWPCE PCE4NOTE` read the visit off the TIU note and ignore DFN, so `ClinicalEvent.visit_for_note`, `has_visit?`, `visit_status` and `pce_for_note` returned another patient's encounter for any note IEN. They now read the note's patient first with `TIU GET ALERT INFO` (`GETALRT^TIUSRVR`, read-only; new mapping `DataMapper[:tiu_note_patient]`), under `OR CPRS GUI CHART`, the only option that registers it, and restore the caller's context. The ORWPCE RPC is sent only when that patient is the DFN passed.
- Otherwise they raise `RpmsRpc::ClinicalEvent::NotePatientMismatchError` (an `RpmsRpc::Error`, not a broker `RpcError`) and send no ORWPCE RPC. `reason` is `:mismatch` when the note names another patient, and `:unknown` when the reply's first line does not name this note and a positive integer DFN (`-1`, empty, missing or non-integer pieces) or when the server answers `served_rpcs` and omits `TIU GET ALERT INFO`. The message never carries the DFN the note belongs to. A broker error from the ownership read propagates unchanged.
- Note 0 (the location lookup, which the server does by DFN) and invalid arguments are unchanged and make no ownership read. `note_visit_string` stays unscoped: `ORWPCE NOTEVSTR` takes no DFN, and its doc now says so. `TIU GET ALERT INFO` is listed under `RpmsRpc::ClinicalEvent` in `required_rpcs.json`. A `MockClient` host must seed the note's patient (`seed_raw_lines(:tiu_note_patient, note, ["note^DFN^tab"])`) or these reads raise `:unknown`.

A clinic's scheduling settings, providers, users and letters, and the access types and resource groups of table maintenance (#739)

- `SchedulingSetup.clinic_settings` reads a clinic's HOSPITAL LOCATION (#44) and CLINIC SETUP PARAMETERS (#9009017.2) settings and its providers; `update_clinic_settings` files changes one field at a time with DDR FILER and the `E` flag, so FileMan validates each (input transforms, pointer screens), tries a refused field once more after the rest, and names each field it still refuses.
- `SchedulingSetup.letters` lists LETTER (#407.5) with its type; `clinic_providers`, `add_clinic_provider` (checked with DDR VALIDATOR first), `set_default_provider` and `remove_clinic_provider` keep the PROVIDER multiple (#44.1); `resource_users` and `set_master_overbook` read and set BSDX RESOURCE USER rights; `resource_groups` lists every BSDX RESOURCE GROUP with its resources.
- `SchedulingSetup.access_types` carries each type's colour (`"#RRGGBB"` from RED, GREEN and BLUE, or nil).
- New `SchedulingMaintenance`: `save_access_type`, `save_resource_group`, `add_resource_group_member`, `remove_resource_group_member`, `save_resource_user` and `remove_resource_user`, through the BSDX add/edit RPCs Windows Scheduling sends, each bound to BSDXRPC. The built BSDX ADD/EDIT RESOURCEUSER answers a success with its header alone, so `save_resource_user` reads the entry back, and it refuses a resource BSDX RESOURCES does not list before the write.

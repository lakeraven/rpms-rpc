`Problem.details` returns ORQQPL DETAIL's report text, not a caret row (#821)

`Problem.details(dfn, ien)` returns the display report DETAIL^ORQQPL builds, one
line per node joined with newlines: `NARRATIVE (DIAGNOSIS)`, then the labelled
Onset, Status, SC Cond, Exposure, Provider, Clinic, Recorded, Entered and Updated
lines (ORQQPL.m:21-59). It read the reply as one caret row, so the first line
landed in `:ien` and `:status` and `:description` were nil. DETAIL never reads
DFN, and a problem not on file dies in M (LVUNDEF), which raises. A live spec as
PROVIDER,TEST on bcer-9.0-20261119-f67498c-ydb-demo proves the report, and
`problem_test.rb`'s details cases replay replies captured there.

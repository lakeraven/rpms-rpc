`HealthSummary.for_patient` prints the IHS health summary type the build has (#662)

- `for_patient(dfn, summary_type: "ADULT REGULAR")` now resolves the type, by name in any case or by IEN, against the build's IHS HEALTH SUMMARY TYPE file (#9001015, read through DDR LISTER; `HealthSummary.summary_types` lists it) and runs the IHS report (`ORWRP REPORT TEXT` with RPTID `IHS`, HS^ORWRPBHS) for that IEN. It used to send report 1 with type IEN 1 from an invented table (STANDARD, BRIEF, COMPREHENSIVE, PATIENT): report 1 reads HSTYPE as a VA type (#142), and VA type 1 faults (`ERR+9^ORWRP`).
- A type that is not on file sends no report and answers an error summary naming it, instead of falling back to another type. A report that faults on the server is an error summary.
- Sections are the report's own banners (`ACTIVE PROBLEMS (ALL)`, `CURRENT MEDICATIONS (max 6 visits or 6 months)`, ...). Page banners are dropped and a section that runs onto the next page is one section. `component_data` picks the section whose banner is, or ends with, the component's name.
- Proven live on a throwaway container of bcer-9.0-20261109-d3adcff-ydb as PROFILE,MD and PROFILE,RN: every listed type prints without a fault (`test/live/health_summary_live_test.rb`), with the replies pinned as captures.

`BehavioralHealth::Wellness` files a visit's screenings and measurements (#540)

- `save_screening` locks `^AMHREC(record)` (`DDR LOCK/UNLOCK NODE`, five seconds) before reading #9002011 (patient `.08`, signature `1112`, and the fifteen screening fields). DDR reads and the lock run under `CIAV VUECENTRIC`, because `AMHGRPC` does not register them; the write runs under `AMHGRPC`. The write is `AMHG SAVE SCREENING`: mode `E`, nineteen pipe pieces, external set names for results, and every screening the caller did not name resent from that read. `SCREEN^AMHGEVF` files all fifteen fields with `FILE^DIE("K")`, so an omitted comment or provider is sent blank and clears the field. `FILE^DIE("K")` takes an incremental lock on the same node, so holding `^AMHREC(record)` does not block it. A supplied comment must be 2 to 245 characters and must not contain a pipe, a caret, a control character, or U+FFFD. A stored comment that contains U+FFFD is not resent. Each distinct provider IEN the screening write will send — a caller-supplied IEN, or one resent from a screening the caller did not name — is confirmed once on file 200 (field `.01`) before the write. A stored provider that is not on file raises `SaveError` before `AMHG SAVE SCREENING` is sent. Each save captures `RpmsRpc.client` once and runs the lock, the reads, the write, the read-backs, and the unlock inside `RpmsRpc.with_client` on that object, so a later change to the configured client does not move the save. Once `DDR LOCK/UNLOCK NODE` has been sent, that node is unlocked before a lock failure is reported, including when the call raised `StandardError` or `NotImplementedError` or returned anything other than true (`L -` on a node not held is harmless). The failure is `SaveError` and that exception is its cause. A lock that was acquired is released after the read-back. The unlock runs only on that captured client. An unlock that raises `StandardError` or `NotImplementedError`, or returns false, does not change the result or replace an exception already in flight; a lock it does not release expires with the broker job. M's lock is incremental, so a second save on the same broker job would be granted `^AMHREC(record)` immediately. A process-level exclusion keyed by the record IEN and the captured client's identity, guarded by a mutex that is never held across the save, raises `SaveError` before any RPC while that pair is in progress (the message says the save is in progress) and releases the key when the save returns. The identity is `session_id` when the captured client responds to `session_id` and that call returns a non-nil, non-empty value; otherwise it is the captured client's own `object_id`. The key is `[:session, id]` or `[:object, object_id]` with the record IEN, so a session id cannot collide with an object id. `session_id` is evaluated once per save; if that call raises, the save fails closed with `SaveError` before any RPC. A different record, or a later call, is not refused. A field absent from the post-write read of the fifteen screening fields is a mismatch, never a blank. `NotImplementedError` from a DDR call before the write is `SaveError`. This file loads `Patient` before the FileMan call so `Patient::FILEMAN_CONTEXT` resolves when the module is required on its own.
- `save_measurements` uses the same captured client, visit lock, and FileMan context, then sends `AMHG SAVE MEASUREMENTS` in mode `A` (`TYPE~~VALUE~PROV` joined by `*`). Mode `E` would delete measurements the call did not list. Values are integers in the instrument range (PHQ9 and PHQT 0-27, PHQ2 and GAD2 0-6, GAD7 0-21). After the write it re-reads the visit and `AMHG GET VISIT MSR DATA ENTRY`, whose BMXIEN column is the measurement-type IEN. A row of a type that was sent must be an integer with a positive type IEN and a provider IEN. A row of any other type is kept, and a non-integer value stays a string; it does not fail the save. A row with the wrong number of columns does.
- Both methods refuse a lock that was not acquired, a missing visit, a patient that is not field `.08`, a provider that is not on file 200, or a non-empty `1112` (the note is signed) before the write. After the write RPC is sent, anything that is not a proven record IEN plus a matching read-back — including a visit that cannot be re-read or whose patient changed, read-back text that contains U+FFFD, and any `StandardError` or `NotImplementedError` from the write, the post-write visit read, or the measurement read-back — raises `Wellness::SaveError` and says the record may have been filed. `RpcMError`, `TimeoutError`, `ConnectionError`, `Timeout::Error`, and any other such exception are that same error and keep their cause. The unlock still runs and does not replace that outcome. Messages do not include comment text.

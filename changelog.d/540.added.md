`BehavioralHealth::Wellness` files a visit's screenings and measurements (#540)

- `save_screening` locks `^AMHREC(record)` (`DDR LOCK/UNLOCK NODE`, five seconds) before reading #9002011 (patient `.08`, signature `1112`, and the fifteen screening fields). DDR reads and the lock run under `CIAV VUECENTRIC`, because `AMHGRPC` does not register them; the write runs under `AMHGRPC`. The write is `AMHG SAVE SCREENING`: mode `E`, nineteen pipe pieces, external set names for results, and every screening the caller did not name resent from that read. `SCREEN^AMHGEVF` files all fifteen fields with `FILE^DIE("K")`, so an omitted comment or provider is sent blank and clears the field. `FILE^DIE("K")` takes an incremental lock on the same node, so holding `^AMHREC(record)` does not block it. A supplied comment must be 2 to 245 characters and must not contain a pipe, a caret, a control character, or U+FFFD. A stored comment that contains U+FFFD is not resent. Each distinct provider IEN the screening write will send — a caller-supplied IEN, or one resent from a screening the caller did not name — is confirmed once on file 200 (field `.01`) before the write. A stored provider that is not on file raises `SaveError` before `AMHG SAVE SCREENING` is sent. Each save captures `RpmsRpc.client` once and runs the lock, the reads, the write, the read-backs, and the unlock inside `RpmsRpc.with_client` on that object, so a later change to the configured client does not move the save. Once `DDR LOCK/UNLOCK NODE` has been sent, that node is unlocked before a lock failure is reported, including when the call raised `StandardError` or `NotImplementedError` or returned anything other than true (`L -` on a node not held is harmless). The failure is `SaveError` and that exception is its cause. A lock that was acquired is released after the read-back. The unlock runs only on that captured client. An unlock that raises `StandardError` or `NotImplementedError`, or returns false, does not change the result or replace an exception already in flight; a lock it does not release expires with the broker job. M's lock is incremental, so a second save on the same broker job would be granted `^AMHREC(record)` immediately. A process-level exclusion keyed by the record IEN and the captured client's identity, guarded by a mutex that is never held across the save, raises `SaveError` before any RPC while that pair is in progress (the message says the save is in progress) and releases the key when the save returns. No client this gem ships defines `session_id` (`CiaClient` has `session_uid`; `XwbClient`, `BmxClient`, `MockClient` have neither), so with stock clients the guard keys on the captured client's `object_id`, and two different wrapper objects around one session do not share the exclusion. A host that wraps one session in several objects must expose `session_id` on them to share the guard. When the captured client responds to `session_id` and that call returns a non-empty String or a non-String value other than nil or false, the key is `[:session, id]`; otherwise it is `[:object, object_id]`, with the record IEN, so a session id cannot collide with an object id. `session_id` is evaluated once per save; if that call raises, the save fails closed with `SaveError` before any RPC. A different record, or a later call, is not refused. A field absent from the post-write read of the fifteen screening fields is a mismatch, never a blank. Any `StandardError` or `NotImplementedError` from a DDR call before the write is `SaveError`, and that exception is its cause. A `#9002011` or file `200` reply from `DDR GETS ENTRY DATA` that `RpmsRpc::Reply` marks altered, or that has a line outside a word-processing block which is not a `FILE^IENS^FIELD^VALUE` row, is not a usable read. `DDR GETS ENTRY DATA` emits only `[Data]` and `[ERROR]`. `[Data]` is a marker only as the first line of the reply; any later `[Data]` sets `stray: true`. `[ERROR]` stays a marker. Any other line that starts with `[` sets `stray: true` and is skipped, and the lines after it are parsed. A second row for a field already parsed, plain or word-processing, sets `stray: true`; the later row is the value stored. `DdrFileman.gets_entry` adds `altered: true` or `stray: true` for those cases and omits each key when it is false, so a well-formed reply keeps `fields`, `error`, and `malformed` only. A visit read is usable only when its parsed field keys are exactly patient `.08`, signature `1112`, and the fifteen screening fields: every one present, and no other. A missing row is not usable, on the pre-write read and on the read-back. `CiaClient#call_rpc` splits the body with a limit of -1. One trailing empty fragment is dropped without marking the reply altered. A single final `$C(31)` fragment is the clean GLOBAL ARRAY end node only when the body contains no CR or LF; that node, and the one terminator that may follow it, are dropped without marking the reply altered. A body that contains a CR or LF and drops a `$C(31)` fragment anywhere, including last, marks the reply altered. A `$C(31)` fragment anywhere other than that clean end node, or more than one trailing empty fragment, marks the reply altered, so a stored comment is not resent from a shortened line. Before the write that read is `SaveError` and the AMHG RPC is not sent. This file loads `Patient` before the FileMan call so `Patient::FILEMAN_CONTEXT` resolves when the module is required on its own. `Wellness::SaveError` subclasses `BehavioralHealth::SaveError`, including when this file is required without `behavioral_health.rb`.
- `save_measurements` uses the same captured client, visit lock, and FileMan context, then sends `AMHG SAVE MEASUREMENTS` in mode `A` (`TYPE~~VALUE~PROV` joined by `*`). Mode `E` would delete measurements the call did not list. Values are integers in the instrument range (PHQ9 and PHQT 0-27, PHQ2 and GAD2 0-6, GAD7 0-21). After the write it re-reads the visit and `AMHG GET VISIT MSR DATA ENTRY`, whose BMXIEN column is the measurement-type IEN. A row of a type that was sent must be an integer with a positive type IEN and a provider IEN. A row of any other type is kept, and a non-integer value stays a string; it does not fail the save. A row with the wrong number of columns does.
- Both methods refuse a lock that was not acquired, a missing visit, a patient that is not field `.08`, a provider that is not on file 200, an altered or stray visit or provider DDR reply, a visit read whose parsed field keys are not exactly the visit field list, or a non-empty `1112` (the note is signed) before the write. From `AMHG SAVE SCREENING` and `AMHG SAVE MEASUREMENTS`, `Client::RpcNotAvailableError` and `Client::RpcRefusedError` propagate unchanged. `Client::FrameTooLongError` from those two calls is `Wellness::SaveError`, the cause is kept, and the message says the call could not be framed and nothing was sent. Any other `StandardError` or `NotImplementedError` from those calls is `Wellness::SaveError`, says the record may have been filed, and keeps the cause. After the write RPC is sent, anything that is not a proven record IEN plus a matching read-back — including a visit that cannot be re-read (an altered reply, a stray line, parsed field keys that are not exactly the visit field list, or a changed patient) or whose read raises, read-back text that contains U+FFFD, and any `StandardError` or `NotImplementedError` from the post-write visit read or the measurement read-back, including `RpcNotAvailableError` on that read-back — raises `Wellness::SaveError` and says the record may have been filed. `RpcMError`, `TimeoutError`, `ConnectionError`, `Timeout::Error`, and any other such exception on those paths are that same error and keep their cause. The visit unlock still runs on the captured client for each of these outcomes and does not replace an exception already in flight. Messages do not include comment text.

# Registration and scheduling writes (rpms-rpc#418)

Evidence is from the pinned bcer YDB build: a tag-level reverse call graph over the routines in `/data/r` (external `TAG^RTN` refs, local tag refs, and fall-through, depth 6), intersected with every `#8994` `TAG^ROUTINE`. Indirection (`@X`, `XECUTE`) was not followed. `#8994` was read from `^XWB(8994)`.

Resolution 1 is a stock RPC that already reaches the M tag. Resolution 2 is DDR FILER or DDR LISTER, because no `#8994` entry reaches the tag and the FileMan write or read is the whole of what the tag does to those fields. Resolution 3 is not supported: the gem method sends no RPC, because a FileMan write would not be what the M routine does.

## What DDR FILER skips

`DDR FILER` is `FILEC^DDR3` (`DDR3.m:14-18`). Mode `ADD` is `UPDATE^DIE`. Any other mode, including the `EDIT` that deletes a holiday by setting `.01` to `"@"`, is `FILE^DIE`. Both run with no `"E"` flag (`DDR3.m:15,18`), so the value is filed internal. The RPC does not translate an external code, apply a default the M tag would have stuffed, prompt the way an interactive `DIC`/`DIE` does, or update a file the tag updates in its own code.

FileMan triggers and MUMPS cross-references on the fields that are filed still run, because the write is FileMan. That is why the SOGI xrefs and the MBI field triggers do not have to be called by name.

The client supplies the values those tags would have put in the FDA, and nothing else.

Each dated write reads the date row with DDR GETS ENTRY DATA (`.01`, flags `I`, IENS `"<fmdate>,<dfn>,"`) before it files. `S9394^AUPNSOG3` and `SETLSEX` choose that IENS with `$S($D(^AUPNPAT(PAT,92|93|94,EDT)):EDT,1:"+1")` (nodes 92 legal sex, 93 sexual orientation, 94 gender identity). `ADDMBI^AUPNMBI` (`AUPNMBI.m:6`) uses `"?+1"` when `^AUPNPAT(PAT,44,EFFDATE)` exists. A stored `.01` is filed in mode `EDIT` (`FILE^DIE`) at IENS `"<fmdate>,<dfn>,"`. A missing row is mode `ADD` (`UPDATE^DIE`) at `"+1,<dfn>,"` with placeholder 1 DINUM'd to the date (`DDR3.m:12-13`). A nil reply or an error on that read, or on a SOGI value-list read, is `{ success: false, error: :lookup_failed }` and files nothing.

- **Gender identity.** `values` are internal IENs in `#9999999.104`, not labels. Each value is filed once. `S9394^AUPNSOG3` files the value multiple as `FDA(SF,"?+"_CNT_IENS,.01)` with `RES(CNT)` equal to the code IEN, and `G9394^AUPNSOG2` reads that value from the sub-entry subscript, so the subscript has to be the code IEN. Placeholder 1 is the date. Placeholders 2, 3, ... are pinned to each value's IEN. On an existing date, DDR LISTER reads `#9000001.94011` (`.01I`). A sub-entry whose `.01` is not in the new list is deleted (`.01` `"@"`). A code that is not already stored is added, DINUM'd, with those same placeholder numbers starting at 2. `other` is `#9000001.9401` field `2` only when the text is non-blank and a chosen value's field `.02` is `OTH`. That field is piece 2 of the `#9999999.104` 0 node, read with DDR GETS ENTRY DATA (flags `I`). `S9394` receives the text only when `$$GI^AUTSOGI(val,"C")="OTH"`. No such value is `:invalid` and files nothing. A blank `other` does not read the code file. An omitted `date` is the client's today; `FILEC^DDR3` would not default it. `AGI1`/`AGI2` (`AUPNSOGX`) fire on the write. Any code translation or other default inside `SETGI^AUPNSOGI` does not run.
- **Sexual orientation.** Same shape on `#9000001.9301` / `#9000001.93011` and on `^AUPNPAT(PAT,93)`, with values as internal IENs in `#9999999.103`. The OTHER gate is `$$SO^AUTSOGI(val,"C")="OTH"` (field `.02` of `#9999999.103`). `ASO1`/`ASO2` fire. `SETSO^AUPNSOGI`'s own translation and defaults do not run.
- **Legal sex.** `sex` must already be `M`, `F`, or `X`. `MALE` / `FEMALE` are not translated. `source` must already be the `#9000030` IEN. `DATE ENTERED` (field `3`) is the client's `Date.today`, not the server's `DT`. A second call for the same date edits that `#9000001.9201` row in place. `SETLSEX^AUPNSOG3` is not called.
- **MBI write.** The MBI is uppercased here, the way `ADDMBI^AUPNMBI` uppercases it before `UPDATE^DIE`. `DATE ENTERED` is the client's today. `ENTERED BY` is the signed-on `DUZ`; there is no RPC when the client has no `DUZ`. `source`, when given, is filed as field `2` and is not defaulted when omitted. A second call for the same effective date edits that `#9000001.44` row in place. Field `1`'s triggers and xrefs fire. Any other check inside `ADDMBI^AUPNMBI` does not run. An 11-character alphanumeric check is local; FileMan can still refuse the value, and that comes back as `:filer_failed`.
- **MBI read.** This is DDR LISTER, not `GETMBI`/`HISTMBI^AUPNMBI`. Rows are the subfile as stored (`effective_date`, `mbi`, `source`). A "current MBI" choice those tags might make is not applied. A failed read raises `Client::RpcError`; it is not turned into `[]`. Field `1` MBI is required in the DD, so a listed row whose MBI is blank raises `Client::RpcError` as well.

A repeated call for the same date edits the row already stored there, so it does not add a second row and does not come back as "already exists". `retry_safety.yml` still classes `set_gender_identity`, `set_sexual_orientation`, `set_legal_sex`, and `add_mbi` as `non_idempotent_write`. The edit fires the field xrefs again, legal sex and MBI store `DATE ENTERED` as the client's today, and the call binds `CIAV VUECENTRIC` (restore is best-effort). `idempotent_write` in that table is a write the server dedupes, and none of these is. `undo_checkin` stays `non_idempotent_write`: `CHECKIN^BSDX25` still runs, including `BEFORE`/`AFTER^SDAMEVT`, and the read-back only decides what this method reports.
- **Holidays.** `.01` DATE (DINUM) and `2` NAME are the fields that are filed. NAME longer than 30 characters, or blank, is refused before any RPC. `GO^SDHOL`'s interactive `DIC`/`DIE`, and any default it would stuff, does not run. The `B` xref is the file's only xref and FileMan maintains it. Remove looks that xref up with DDR LISTER and deletes by editing `.01` to `"@"`. A date with no row is `:not_found` and does not file. A failed lookup raises; it is not reported as not-found.

## Sex

`SEXELIG^AGUTL` (`AGUTL.m:51`) copies `#2` `.02` into the MCR/MCD/RRE eligibility sub-files (for example `#9000003.11` `.08`). `AG2A.m:58-64` also clears `#9000001` `.23`. That cascade is not a cross-reference on `#2` `.02`, so a DDR FILER write of `.02` would leave eligibility behind. `Registration.set_sex` is resolution 3 and sends no RPC.

`Registration.update(dfn, sex:)` (and `Patient.update`) goes through `Agg.update_patient` / `AGG UPDATE PATIENT` (`UPD^AGGPTUPD`). That RPC files `#2` `.02` from the window parameter `AGGPTSEX` and does not call `SEXELIG^AGUTL`. Passing `sex:` there is not a substitute for `SEXELIG^AGUTL`.

## Undo check-in

`Scheduling.undo_checkin` is resolution 1. It calls `BSDX CHECKIN APPOINTMENT` with check-in time `"@"` and the same eight formals as `checkin_appointment`. `CHECKIN^BSDX25` takes the `"@"` branch and calls `CANCHKIN^BSDX25`, including `BEFORE`/`AFTER^SDAMEVT`. Nothing in that path is reimplemented, and nothing it does is skipped.

`CHECKIN^BSDX25` (`BSDX25.m:54`) clears the check-in only when the appointment's `RESOURCEID` points at a `^BSDXRES` entry, and it replies `"0^"` either way (`BSDX25.m:74`). After that `"0^"` reply, `undo_checkin` reads `#9002018.4` field `.03` with DDR GETS ENTRY DATA (IENS `"<ien>,"`, flags `I`) under `CIAV VUECENTRIC`. An empty `.03` is `{ success: true }`. A value still stored is `{ success: false, error: :not_undone, message: }`. A nil reply or an error on that read is `{ success: false, error: :lookup_failed }`. A check-in reply other than success is returned as `checkin_appointment` returns it, and `.03` is not read.
